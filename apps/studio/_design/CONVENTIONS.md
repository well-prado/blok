## 2. The variant pattern — plain object + `cn()`

**DECIDED: a `const variants` lookup object typed `as const`, combined with the existing `cn()`. No `class-variance-authority`. No shared `createVariant` helper. No `tv`/`tailwind-variants`.**

Why this and not cva: cva is *not installed* in this repo (verified), and in the trigger.dev reference it is installed but used in exactly **1 of 80+ primitives** — the pattern that actually won there is the plain object. `keyof typeof variants` infers the union with zero generics, which matters under this repo's no-`any` rule. Adding a dependency to do a `Record` lookup fails the ladder at rung 5.

Why no shared `createVariant`: trigger.dev's `createVariant` exists only to build a 5×9 size×theme cross-product of six-slot records. No Studio primitive has 33 variants. More importantly, a shared variant helper is a *shared file*, i.e. a seven-way collision point. If your primitive genuinely needs a cross-product, write an 8-line builder **inside your own file** and do not export it.

### 2.1 Canonical single-slot form (use this ~90% of the time)

```tsx
import { cn } from "@/lib/utils";

const variants = {
	default: "bg-control text-ink border border-line",
	danger: "bg-status-failed/10 text-status-failed border border-status-failed/30",
} as const;

const sizes = {
	sm: "h-6 px-2 text-xs",
	md: "h-8 px-3 text-sm",
} as const;

type BadgeProps = React.ComponentPropsWithRef<"span"> & {
	variant?: keyof typeof variants;
	size?: keyof typeof sizes;
};

export function Badge({ className, variant = "default", size = "md", ...props }: BadgeProps) {
	return <span className={cn("inline-flex items-center rounded", variants[variant], sizes[size], className)} {...props} />;
}
```

`src/components/primitives/Spinner.tsx` is this pattern, shipped and working. Read it before you write yours.

Rules baked into that example, all mandatory:
- `as const` on every table. Without it `keyof typeof` widens to `string`.
- **`className` is always the last argument to `cn()`**, so callers can override. Always accept and forward `className`.
- Always spread `...props` onto the root element.
- Extend the native element's props (`React.ComponentPropsWithRef<"span">`). Never invent a parallel prop bag. Never `any`.

### 2.2 Multi-slot form (only when a variant must style more than one element)

The table value becomes an object. Do not generalize this into a helper.

```tsx
const variants = {
	primary: { root: "bg-accent", label: "text-on-accent", icon: "text-on-accent/70" },
	secondary: { root: "bg-control", label: "text-ink", icon: "text-ink-muted" },
} as const;
```

### 2.3 Spacing rule (typography only)

Typography primitives ship **zero margins by default**. Each variant carries `{ text, spacing }` and `spacing` is applied only under an opt-in `spacing?: boolean` prop defaulting to `false`. A primitive must never fight its container's layout.

### 2.4 `ref` — no `forwardRef`

Studio is React 19 with no SSR. `forwardRef` is deprecated. Declare `ref` as a plain prop: `React.ComponentPropsWithRef<"button">` already includes it.
**One exception:** inside a Radix wrapper file, copy Radix's own `React.forwardRef` idiom verbatim — their types expect it and fighting it costs more than it saves.

## 3. Token vocabulary — the ONLY colors that exist

`app.css` is a three-layer system. **You consume layer 2 and layer 3. You never name layer 1, and you never edit any of it.**

Layer 1 is the raw ramps (`--color-graphite-*`, `--color-blok-green-*`). Layer 2 is the semantic indirection. Layer 3 is status. `/catalog/foundation` renders every token on this page — look at it.

### 3.1 The complete vocabulary

**Surfaces** (background ladder, deepest → most raised)
| Token | Utility | Use for |
|---|---|---|
| `canvas` | `bg-canvas` | app background |
| `raised` | `bg-raised` | cards, panels |
| `overlay` | `bg-overlay` | dialogs, popovers, menus, tooltips |
| `hover` | `bg-hover` | hover state on a surface |
| `control` | `bg-control` | inputs, buttons, chips |

**Ink** (text, strongest → faintest)
| Token | Utility | Replaces |
|---|---|---|
| `ink-strong` | `text-ink-strong` | `text-zinc-100/50/200` |
| `ink` | `text-ink` | `text-zinc-300` |
| `ink-dimmed` | `text-ink-dimmed` | `text-zinc-400` |
| `ink-muted` | `text-ink-muted` | `text-zinc-500` |
| `ink-faint` | `text-ink-faint` | `text-zinc-600` |

**Lines**
| Token | Utility | Replaces |
|---|---|---|
| `line` | `border-line` | `border-zinc-800` |
| `line-strong` | `border-line-strong` | `border-zinc-700` |
| `line-bright` | `border-line-bright` | `border-zinc-600` |

**Accent**
| Token | Utility | Use for |
|---|---|---|
| `accent` | `bg-accent` / `text-accent` | primary CTA, brand |
| `accent-hover` | `bg-accent-hover` | its hover |
| `on-accent` | `text-on-accent` | text **on** an accent fill (replaces the 21 `text-[#00231b]`) |
| `focus-ring` | via `.focus-ring` utility | focus treatment |

**Status** — all 14 `WorkflowRunStatus` members have a token: `status-{pending,running,paused,completed,failed,cancelled,skipped,throttled,delayed,expired,debounced,queued,crashed,timedOut}` plus `status-warning`. Logs: `log-{debug,info,warn,error}`.

Note the camelCase in `status-timedOut` — it matches the type union member and Tailwind emits `bg-status-timedOut` for it.

Opacity modifiers work on every one of these (`bg-status-failed/10`, `border-accent/30`) — Tailwind v4 lowers them via `color-mix`.

### 3.2 The hard rule

**Inside any file you create, these are banned:**
- any `zinc|gray|slate|neutral|stone` color class
- any hex literal
- any arbitrary color value: `text-[#00231b]`, `bg-[rgb(...)]`
- any trigger.dev token name pasted from the reference: `text-text-bright`, `text-text-dimmed`, `bg-background-raised`, `border-border-bright`, `bg-tertiary`, `focus-custom`, and the `system:` / `light:` variants. **These tokens do not exist in Studio and Tailwind emits nothing for them — your component silently renders unstyled.** This is the single most likely way to ship a broken primitive.

Non-color raw Tailwind (spacing, radius, `flex`, `text-sm`) is fine and expected. So is `text-[10px]` — the guard only rejects arbitrary values that are colors.

A test enforces this (§8.4). It will fail your PR, not a reviewer.

### 3.3 Semantic colors that are not neutrals

`blue`, `red`, `amber`, `green` etc. as raw classes are also banned in your files — use the `status-*` / `log-*` tokens, which is what they exist for. If you need a color with no token, you have found a genuine gap: **stop and report it upward rather than inventing a hex.** Do not edit `app.css` to add one.

### 3.4 Focus

Every interactive element MUST be focus-visible. Use the foundation's utility:

```tsx
<button className={cn("focus-ring", ...)}>
```

`.focus-ring` is defined in `app.css` as `outline: 1px solid var(--color-focus-ring); outline-offset: -1px`. The **inset** offset is deliberate — a 0-offset outline gets clipped by `overflow:hidden` scroll ancestors, of which Studio has many. Do not substitute `ring-2 ring-blok-green-400`.

## 7. The catalog — one file, zero shared edits

The catalog lives at `/catalog` and its nav is **derived from a glob**, so adding your page registers it with no shared-file edit. This is the whole reason the design is safe for seven parallel agents.

Mechanically: `src/lib/catalogPages.ts` runs a non-eager `import.meta.glob("../catalog/*.tsx")`, derives `{ slug, label, load }` from each filename, and sorts by slug. The nav, the index list and the `$page` route all read that one array. `src/catalog/` deliberately sits **outside** `src/routes/`, so TanStack Router's generator never sees your page and `routeTree.gen.ts` never changes. Non-eager means each page is its own lazily-loaded chunk.

**You create exactly one file: `apps/studio/src/catalog/<your-slug>.tsx`.**

### 7.1 Required page shape

```tsx
// apps/studio/src/catalog/buttons.tsx
import { CatalogPage, Variant } from "@/components/catalog/CatalogPage";
import { Button } from "@/components/primitives/Buttons";

export default function ButtonsCatalog() {
	return (
		<CatalogPage title="Buttons" description="Every variant × size × state.">
			<Variant label="Variants">
				<Button variant="primary">Primary</Button>
				<Button variant="secondary">Secondary</Button>
				<Button variant="danger">Danger</Button>
			</Variant>
			<Variant label="Sizes">
				<Button size="sm">Small</Button>
				<Button size="md">Medium</Button>
			</Variant>
			<Variant label="Disabled">
				<Button variant="primary" disabled>
					Primary
				</Button>
			</Variant>
		</CatalogPage>
	);
}
```

`src/catalog/foundation.tsx` is a working example. Copy its shape.

### 7.2 Catalog rules (all mandatory)

- **Default export only**, and its root element MUST be `<CatalogPage>`.
- One `<Variant label="…">` per axis. Show **every** variant, **every** size, and the disabled/loading/error states.
- **Tailwind scans source text, so class names must be written out literally.** A computed `` bg-${token} `` emits nothing and your swatch renders blank. Use a literal table (see `foundation.tsx`).
- **No data fetching.** Never import `@/lib/api` and never call a `useX()` hook that fetches. Catalog pages are lazily chunked; a static import of `api.ts` from a lazy chunk creates a static/dynamic conflict and worsens bundle chunking (there is already one such warning in this app — do not add a second).
- Presentational imports only.
- Your slug is assigned in §12. **Do not create a page for a slug you were not assigned** — two agents creating `src/catalog/badges.tsx` is a real conflict on a supposedly-unshared file.

## 9. Accessibility baseline — every primitive, no exceptions

This is the one area where "lazy" does not apply. Minimum bar:

- **Keyboard reachable and operable.** Anything clickable is a `<button>`/`<a>` or has `role` + `tabIndex` + key handlers. No `onClick` on a bare `<div>`.
- **Visible focus** via `.focus-ring` (§3.4).
- **Accessible name** on every control. Icon-only buttons MUST carry `aria-label`; their icon MUST be `aria-hidden="true"`.
- **Decorative icons are `aria-hidden="true"`** always.
- **`title=` is BANNED as a tooltip mechanism** in new code. It is touch-inaccessible and unstyleable. Use T7's Tooltip once available; until then, a visible label.
- **Never add a `biome-ignore lint/a11y/*` suppression.** There are 9 in the codebase already; adding a tenth in a *new design system* fails review. If you need one, your markup is wrong.
- Form controls (T5): every input has an associated `<label>`; error text is wired via `aria-describedby`; invalid inputs carry `aria-invalid`.
- Overlays (T8): Radix supplies focus trap, focus return, and `aria-modal`. Do not disable them. Every Dialog needs a `DialogTitle` (Radix warns at runtime without one).

## 10. Theme — dark-only today, light-ready by construction

**DECIDED: Studio ships dark-only in E1. You write NO `dark:`, `light:`, or `system:` variants.**

The token layer is nonetheless built two-layer (raw palette → semantic `var()` indirection) specifically so that light mode later is a **CSS-only change in `app.css`** — a scoped `[data-theme="light"]` block re-maps the semantic layer and nothing else. That property only holds if you obey §3.2. **Every raw `zinc-*` you write is a pixel light mode can never reach.** That is the actual reason the token rule is enforced by a test.

Corollary: never re-map a semantic token yourself, and never reference the raw ramp (`graphite-*`) directly — always the semantic name.
