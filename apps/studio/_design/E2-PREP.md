## 1. The one thing that makes E2 different from E1

E1 fanned out 7 ways with **zero merge conflicts** because each agent owned distinct files —
`Buttons.tsx`, `Headers.tsx`, `Tooltip.tsx` … and one auto-registering catalog page each.

**E2 does not have that property.** All seven tasks converge on a single component. trigger.dev's
`Table.tsx` is 651 lines and the tickets describe sort, hover/focus, row actions, selection,
virtualization and blank states as facets of *that one file*. A naive 7-way fan-out puts seven
agents in the same 651 lines and produces seven-way conflicts on every merge.

**So E2 must be sequenced by coupling, not split by ticket.** The wave shape in §5 reflects that.

The corollary, which is the hardest-won E1 lesson: **legislate the shared axes BEFORE the fan-out.**
E1's seven agents converged perfectly on every axis the contract legislated (size ladder, radius,
disabled, focus) and diverged on every axis it did not (four meanings for `variant`, two names for
red, three shadow tiers) — costing a whole reconciliation round. For E2, the contract additions in
§4 must land in Wave A, not be reconciled afterwards.

## 2. E1 lessons that must carry forward

**2.1 The recurring failure: the fix is right, the guard is hollow.** Three separate rounds shipped
a correct fix with no test that could fail on its revert. Twice a reviewer reverted a shipped fix
and watched the suite stay green — once at 457/457, once at 643/643 *with `ci:fast` at exit 0*.
→ Every E2 agent must prove its fix fails without itself (mutate, run, restore) and quote the
failure. Every reviewer must attempt the revert rather than read the diff.

**2.2 Browser-only defects exist and no gate sees them.** `MiddleTruncate` corrupted the clipboard
(sr-only twin in the selection flow → copied id doubled); the focus ring faded in from each
element's own text color (Tailwind v4 folds `outline-color` into `transition-colors`). jsdom has no
selection model, no layout, no real focus paint. → Table work is *even more* layout-dependent
(sticky headers, virtualization, row focus). Require live-browser measurement, not screenshots:
`getBoundingClientRect`, `getComputedStyle`, real `Tab` keypresses.

**2.3 Contract text is executable and gets stale.** After renaming `danger`→`error`, §7.1's
copy-paste template still said `variant="danger"` — the block every agent is handed taught code
that does not compile. → After any rename in E2, grep CONVENTIONS.md itself.

**2.4 An agent will restate a spec's claim as fact.** One agent reported
`_design/trigger-dev-parity.md` "does not exist — confirmed"; it existed but was **untracked**, so
invisible from every worktree. Now committed. → Verify a "missing" file against `git ls-files`.

**2.5 Reviewers earn their cost.** Of 5 review rounds, 4 returned FIX_FIRST with reproducible
defects, including a real WCAG regression framed as cleanup. Do not skip the adversarial phase.

**2.6 Tetrix specifics.** `github:triggerdotdev/trigger.dev` is indexed (4921 files / 38899 symbols)
and is the highest-value tool in this epic — read the real source, do not infer from ticket prose.
`github:well-prado/blok` is indexed but **stale** (2026-08-10, ~30 commits behind, contains none of
E1) — orientation only, re-confirm locally. `get_impact_analysis` / `get_symbol_dependencies`
return `found:true` with **empty graphs** for this repo: try once, then grep, and say which you used.
`search_code` needs `repository_id` or it returns nothing. `list_documents` holds zero
standard/skill docs — do not hunt.

**2.7 Mechanics that cost time in E1.**
- Agent worktrees have **no node_modules** → `bun install` first, always.
- The frozen `__tests__/catalog.test.tsx` renders every catalog page **bare, with no
  `RouterProvider`** → a TanStack `<Link>` in a catalog page crashes it. E1's workaround:
  `useRouter({ warn: false })` gate. Table rows will want links — **solve this properly in Wave A**.

## 3. Collision map (why the waves are shaped this way)

| task | primary surface | conflicts with |
|---|---|---|
| T1 table primitive + variants + sticky | `Table.tsx` (new) | — it IS the substrate |
| T2 sort | `Table.tsx` header cells | T1, T3, T6 |
| T3 row hover/focus/keyboard | `Table.tsx` row + focus model | T1, T2, T5, **T6 hard** |
| T4 row action menus | new `TableRowActions.tsx` + a row slot | T1 (slot only) |
| T5 selection + bulk bar | new `useTableSelection` + `BulkActionBar.tsx` + a cell slot | T1 (slot only) |
| T6 virtualization | **replaces the rendering model** in `Table.tsx` | T1, T2, T3, sticky headers |
| T7 blank / no-results | new `TableBlankState.tsx` + a body slot | T1 (slot only), E11 overlap |

**T6 is the structural risk.** Virtualization changes how rows are rendered, which breaks naive
sticky headers and any focus model that assumes all rows are in the DOM. It cannot be bolted on by
a blind parallel agent. Two options, to decide in Wave A with the research dossier in hand:
 (a) design the windowing seam into T1 up front and have T6 fill it, or
 (b) ship T1–T5/T7 non-virtualized and treat T6 as a follow-on refactor with its own review.
Recommend (a) — a rendering-model change after five features have landed on the old model is the
expensive version.

**T4/T5/T7 are genuinely parallelizable** *if* T1 defines their slots first. They are mostly new
files consuming E1 primitives (`DropdownMenu`, `Checkbox`, `Button`, `EmptyState`).

## 4. Contract additions that MUST land in Wave A (before any fan-out)

Add to `_design/CONVENTIONS.md`, same binding style as §2.4/§2.9/§2.10:

1. **Density ladder.** The tickets call for `bright`/`dimmed` variants driving header, cell,
   cellSize and cellText *together*. Name the rows and their exact heights/padding/text, the way
   §2.4 does for controls. This is the E2 analogue of the size ladder — the axis most likely to
   fragment across agents. NB **E16-T5 (#862) is a density toggle** — make this ladder its substrate.
2. **The row-slot contract.** Exact API by which T4 (actions), T5 (checkbox), T7 (blank body) plug
   into a row/body without editing `Table.tsx`. This is E2's equivalent of E1's catalog glob — the
   single mechanism that makes parallelism possible. Get it right or the wave serializes.
3. **Selection state ownership.** Who owns selected-row state (hook vs context vs caller), so T5's
   bulk bar and T3's keyboard nav do not invent two models.
4. **Table a11y baseline.** Real `<table>` semantics vs ARIA grid; where focus lives (row vs cell);
   what `aria-sort`, `aria-selected`, `aria-rowcount` are required; how virtualization must keep
   `aria-rowcount`/`aria-rowindex` honest. Decide **before** T3 and T6 disagree.
5. **Empty vs no-results.** #784 and **E11-T4 (#839)** overlap explicitly ("nothing yet" vs "no
   results for this filter"). State which epic owns the component and which consumes it.
6. **Sort/filter URL state.** #789 (E3) syncs filter state to URL params. If T2's sort state also
   belongs in the URL, say so now so E3 does not re-litigate it.

## 7. Research findings that CHANGE this plan

Added after `E2-RESEARCH.md` landed. Where §3/§5 disagree with this section, **this section wins.**

**7.1 trigger.dev does not virtualize tables at all.** `Table.tsx` and `TaskRunsTable.tsx` render
`runs.map(...)` — every row, always — and get away with it via server-side cursor pagination. The
only virtualized surface in the whole reference app is the span `TreeView`. So #783 is not "match
the reference", it is "go beyond it", and the §3 framing of T6 as *the* structural risk is
overstated: nothing in Studio today exceeds ~50 rows, because every list is paginated. The log
stream (E10) is the only genuinely unbounded list.
→ Revised recommendation: **build the seam in T1, defer the implementation.** `<TableBody>` accepts
`rows` + `renderRow` as an alternative to `children` (~6 lines), so T6 later changes one component's
internals and nothing else. Window with two spacer `<tr>`s — never absolute positioning, or the
`<table>` stops being a real table and sticky `<thead>` dies. Threshold-gate at ~100 rows exactly
like the existing `StepRail.tsx`.

**7.2 `@tanstack/react-virtual@^3.11.0` is ALREADY a Studio dependency**, already used in
`src/components/trace/StepRail.tsx`. T6 adds no package. StepRail's `count: useVirtual ? n : 0`
threshold gate is also why its jsdom tests pass with no `ResizeObserver` polyfill — `setup.ts` has
none, so any virtualization test must keep that gate or add a polyfill.

**7.3 The reference's `variant` fuses three axes** — density (`cellSize`), surface/hover
(`header`/`cell`/`stickyCell`) and font family (`font-mono` inside `compact`/`mono`). Copying it
verbatim reintroduces exactly the §2.10 collapse E1 spent a reconciliation round undoing. The
density ladder must be split out cleanly.
→ **Founder decision:** add `density` as a FIFTH reserved prop axis in §2.10, rather than overloading
`size`. The dossier's argument is concrete: an `md` table row is 40px while an `md` button is 32px,
so one name cannot carry both. Recommend yes.

**7.4 Four reference a11y bugs to beat, not inherit.** Every sort button is named "Toggle sort";
the sort target is a ~16px chevron and the header text does nothing (their own code comment says
so); row checkboxes have no accessible name; hover-revealed row actions use `display:none` and are
keyboard-unreachable. Blok's `Checkbox` requiring a `label` structurally prevents the third. Make
all four MUST rules in the §4 a11y baseline.

**7.5 There is no bulk-action bar in the reference** — selection drives a count `Badge` plus a
resizable side panel. Blok's existing `src/components/runs/BulkActionToolbar.tsx` is closer to
#782's brief than the reference is. T5 should extend Blok's, not transliterate trigger.dev's.

**7.6 E1 GAP: `components/primitives/Text.tsx` never shipped**, although CONVENTIONS §12.1 assigns
it to E1-T4. E2 therefore has no mono/numeric text primitive, which table cells want. Decide in
Wave A: build it as part of T1, or file it as an E1 follow-up.

**7.7 Tooling note for every E2 agent.** Tetrix truncates module fetches at ~200 lines and does not
index `forwardRef` consts; `mcp__github__search_code` returns an auth error but
`mcp__github__get_file_contents` works. The effective workflow is **Tetrix to locate, GitHub
contents to read in full**. `get_impact_analysis` returned `found:false` with empty graphs — same
limitation as E1.
