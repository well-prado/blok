# Inertia real-browser conformance (#1003)

The gate for the SPA epic. One cell is a **disposable project generated by the
real CLI**, built with the real Vite, served by the real HTTP trigger, and
driven by a real Chromium against the stock `@inertiajs/{react,vue3,svelte}`
client. Nothing in it is mocked — not the server, not the bundle, not the
browser, and not the `runtime.python3` sidecar behind the Dashboard's deferred
`stats` prop.

```sh
bun run build                                                  # once
bun run e2e:inertia -- --framework react --mode in-project     # one cell
bun run e2e:inertia -- --framework vue   --mode standalone
bun run e2e:inertia -- --framework react --ssr --repeat 3
bun run e2e:inertia -- --self-check                            # prove it can fail
```

## The matrix

| axis | values |
|---|---|
| `--framework` | `react`, `vue`, `svelte` |
| `--mode` | `in-project` (Blok serves `client/dist`), `standalone` (Vite preview + CORS) |
| `--host` | `node`, `bun` (in-project only) |
| `--ssr` | off, on (React and Vue, in-project only) |

`--repeat N` is N INDEPENDENT scaffolds, builds, servers and browser sessions —
reusing one fixture would hide state that leaks between runs.

Ports are deliberately not the framework defaults (4600 / 4601 / 4673 / 4690 /
10307 / 13814, each overridable with `E2E_*_PORT`): 4321 and 10007 belong to a
developer's own running example, and a suite that stole them would test that.

## What is generated and what is committed

The APP is always `blokctl create project` + `blokctl add spa` (plus
`blokctl create spa` for a standalone client, and a second
`blokctl add spa --kit auth` project for scenario 44). `fixture.ts` then
overlays `fixture/`, which IS committed and is ordinary source: nodes under
`fixture/server/nodes/e2e/`, page workflows under `fixture/server/workflows/`,
the Python node under `fixture/server/python/`, and one client per framework
under `fixture/client/<framework>/`. All three clients expose the same
`data-testid`s, so one spec drives them.

`fixture/client/<framework>/standalone/` holds the two files that differ when
the SPA owns its own origin: an entry that fetches the first page object over
CORS and points the protocol at the backend with `http.setClient()`, and a
`vite.config.ts` with `proxy: false`. `fixture.ts` installs them for standalone
cells and deletes them for in-project ones.

## Environment

- `BLOK_PYTHON=/path/to/python3.12` — `blokctl runtime add python3` builds its
  venv from whatever `python3` is on PATH, and the SDK's typed nodes need 3.11+
  (#1064). The runner puts a shim for this value in front of PATH. In CI,
  `actions/setup-python` does the same job.
- `E2E_KEEP=1` — keep the generated project for inspection (its path is printed).
- `E2E_USE_PUBLISHED=1` + `E2E_PUBLISHED_VERSION=x.y.z` — scaffold from npm
  instead of this checkout. These cells never fall back to the workspace
  packages: a green run against `file:` links would not be evidence about the
  published artifacts.

## The self-check

`bash tests/e2e/inertia/self-check.sh` runs the suite three times with a
deliberately broken proxy in front of the real server:

| flag | breaks | must fail |
|---|---|---|
| `E2E_BREAK_VARY=1` | strips `Vary` | scenario 01 |
| `E2E_BREAK_303=1` | rewrites a 303 to a 302 | scenario 07 |
| `E2E_BREAK_ESCAPE=1` | un-escapes `\/script` in the boot payload | scenario 20 |

A setup or build error is NOT breaker evidence: the check requires Playwright to
have selected the numbered test and reported a failed assertion.
