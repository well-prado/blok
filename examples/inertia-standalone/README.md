# Blok + Inertia v3, standalone (two origins)

The split deployment mode: `backend/` is a Blok server that only answers the
Inertia protocol, `frontend/` is a Vite SPA deployed on its own origin (a CDN,
`:5173`, another host). The two things that make it work are **CORS** and
**generated types**.

Docs: [SPA (Inertia)](../../docs/d/spa/index.mdx) ·
[assets and versioning](../../docs/d/spa/assets-and-versioning.mdx).

## Why this is built by hand

`blokctl create spa` lands with
[#999](https://github.com/well-prado/blok/issues/999), and `@blokjs/inertia` /
`@blokjs/inertia-client` are not published yet. Inside this repository the
example resolves `@blokjs/*`, `@inertiajs/*` and `react` through the **root
install**; it is not a workspace package and has no `node_modules` of its own.

## Layout

```
backend/src/nodes.ts             the prop nodes
backend/src/workflows/orders.ts  two pages, two NAMED routes
backend/src/Workflows.ts         inertia.shared, share(), resolveUrlUsing()
backend/tests/                   the runPage suite — `bun run e2e`
frontend/                        the Vite SPA, `blokInertia({ proxy: false })`
frontend/src/blok-pages.d.ts     GENERATED by `blokctl gen app-types`
frontend/src/blok-routes.ts      GENERATED — the registerRoutes() call
```

## CORS

The backend sends CORS only when `BLOK_CORS_ORIGIN` names the SPA's origin:

```bash
BLOK_CORS_ORIGIN=http://localhost:5173 \
BLOK_FLASH_SECRET=dev-secret \
blokctl dev
```

That turns on `Access-Control-Allow-Credentials: true` plus the full Inertia /
Precognition / DevTools header lists — including
`Access-Control-Expose-Headers`, without which `X-Inertia-Location` and
`X-Inertia-Redirect` are invisible to the client and redirects silently do
nothing.

A value containing `*` turns credentials **off**, and Inertia sends the session
cookie on every visit — so a wildcard origin logs everybody out.

## Types across the repository boundary

The frontend never imports from the backend. It reads generated declarations:

```bash
bun run gen     # blokctl gen app-types --pages-only --dir backend/src/workflows --out frontend/src
```

which writes `frontend/src/blok-pages.d.ts` (augmenting `Pages`, `Routes` and
Inertia's own `InertiaConfig`) and `frontend/src/blok-routes.ts` (the runtime
`registerRoutes()` call). Both are committed here so the example reads as a
finished project; regenerate them whenever a page or route changes.

With those in place the client is fully typed off the server's contract:

```tsx
import { type PageProps, route } from "@blokjs/inertia-client";

function Index({ orders }: PageProps<"Orders/Index">) {
  return <a href={route("orders.show", { id: orders[0].id }).url}>…</a>;
}
```

## Running it

```bash
bun run build          # from the repo root, once
bun run e2e            # the backend's runPage suite — no server, no browser

BLOK_CORS_ORIGIN=http://localhost:5173 BLOK_FLASH_SECRET=dev-secret blokctl dev  # terminal 1
bun run dev:frontend                                                             # terminal 2
```

## `bun run e2e` is a placeholder, on purpose

It runs the backend's `runPage` suite. The real cross-origin end-to-end matrix —
live server, real Vite build, real browsers — is
[#1003](https://github.com/well-prado/blok/issues/1003); when it lands, `e2e`
runs that against this app.
