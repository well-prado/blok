Blok speaks [Inertia.js **v3**](https://inertiajs.com/docs/v3/core-concepts/how-it-works).
You keep the stock `@inertiajs/react | vue3 | svelte` client — nothing is forked,
nothing is wrapped — and the server half is ordinary Blok:

- **a page is a workflow**, declared with `definePage()` and rendered by one
  `page` control step;
- **a prop is a step**, so any prop can run in any runtime (a Python node
  computing `stats` next to a TypeScript node listing `orders`);
- **navigation is the protocol**: the same URL answers an HTML shell on the
  first load and a JSON page object on an Inertia visit.

```ts src/workflows/dashboard.ts
import { defineNode, http, workflow } from "@blokjs/core";
import { always, defer, definePage } from "@blokjs/inertia";
import { z } from "zod";

const currentUser = defineNode({
  name: "current-user",
  description: "The signed-in user.",
  input: z.object({}),
  output: z.object({ id: z.string(), email: z.string() }),
  execute: () => ({ id: "u-1", email: "ada@example.com" }),
});

const listOrders = defineNode({
  name: "list-orders",
  description: "Recent orders.",
  input: z.object({}),
  output: z.array(z.object({ id: z.string(), total: z.number() })),
  execute: () => [{ id: "o-1", total: 120 }],
});

const heavyStats = defineNode({
  name: "heavy-stats",
  description: "Expensive dashboard aggregates.",
  input: z.object({}),
  output: z.object({ revenue: z.number() }),
  execute: () => ({ revenue: 42_000 }),
});

export const Dashboard = definePage("Dashboard", {
  auth: always(currentUser),
  orders: listOrders,
  stats: defer(heavyStats, { group: "dashboard" }),
});

export default workflow(
  "dashboard",
  { version: "1.0.0", trigger: http.get("/dashboard") },
  (req) => {
    Dashboard.render(req, "page", "/dashboard", { auth: {}, orders: {}, stats: {} });
  },
);
```

## The protocol in one table

Everything the adapter reads and writes. The full field-by-field reference is
[The protocol](/d/spa/the-protocol).

| Direction | Name | Meaning |
| --- | --- | --- |
| → request | `X-Inertia: true` | answer with the JSON page object instead of the HTML shell |
| → request | `X-Inertia-Version` | the asset version the client holds; a mismatch on a **GET** forces a hard reload |
| → request | `X-Inertia-Partial-Component` | must equal the page's component, or the visit counts as a full one |
| → request | `X-Inertia-Partial-Data` / `-Partial-Except` | which props to resolve ([partial reloads](/d/spa/partial-reloads)) |
| → request | `X-Inertia-Reset` | return these merge props unmerged ([merging props](/d/spa/merging-props)) |
| → request | `X-Inertia-Except-Once-Props` | cache keys the client still holds ([once props](/d/spa/once-props)) |
| → request | `X-Inertia-Error-Bag` | nest `props.errors` under a bag name ([validation](/d/spa/validation)) |
| → request | `X-Inertia-Infinite-Scroll-Merge-Intent` | `append` / `prepend` ([infinite scroll](/d/spa/infinite-scroll)) |
| → request | `Precognition: true` | dry-run the validation step only ([validation](/d/spa/validation)) |
| ← response | `200 text/html` | first load: the shell with the page object in `<script type="application/json" data-page="app">` |
| ← response | `200 application/json` + `X-Inertia: true` | an Inertia visit: the bare page object |
| ← response | `Vary: X-Inertia` | the same URL serves both |
| ← response | `303` | after a `PUT`/`PATCH`/`DELETE` redirect, never `302` |
| ← response | `409` + `X-Inertia-Location` | asset-version mismatch, or an external `location()` |
| ← response | `409` + `X-Inertia-Redirect` | a redirect to a URL fragment |

## Two deployment modes

<Tabs>
  <Tab title="In-project">
    The SPA lives in `client/` inside the Blok project. Vite builds into
    `client/dist`, the Blok HTTP trigger serves it (`BLOK_STATIC_DIR`), and one
    origin answers everything. In dev, the Vite dev server proxies to Blok, so
    there is still one origin in the browser.
  </Tab>
  <Tab title="Standalone">
    The SPA is its own deployable (a CDN, `:5173`, another host) and talks to
    Blok cross-origin. Blok sends CORS (`BLOK_CORS_ORIGIN`) that must **expose**
    the Inertia response headers, and the types travel through
    `blokctl gen app-types --out ../my-spa/src`.
  </Tab>
</Tabs>

Both are first-class; see [assets and versioning](/d/spa/assets-and-versioning)
for the wiring of each.

For Vercel Functions, same-origin rewrites, Neon/Postgres, and the explicit
limits of SSE, WebSockets, workers, and cron, see [Vercel and serverless
deployments](/d/deployment/vercel).

## Page = workflow, prop = step

`definePage()` declares the contract once, outside the workflow callback, so the
type is importable by the frontend and readable by codegen. `render()` emits
exactly **one** `page` control step, and the runner lowers it to one inner step
per prop (`<pageId>.<key>`) plus the serializer (`<pageId>.$render`).

That means props are ordinary steps: they run **in parallel**, each with its own
`retry`, `idempotencyKey` and `maxDuration`, each persisted to
`ctx.state["<pageId>.<key>"]`, and each free to be a node in another language.
Because they are concurrent, one prop can never read another's output — read the
request, or a middleware's output through [`shared()`](/d/spa/middleware).

| Mode | Full visit | Partial reload | Wrapper |
| --- | --- | --- | --- |
| regular | resolved | when named, or when nothing is named | — |
| `always` | resolved | always, exempt from `only`/`except` | `always(node)` |
| `optional` | never | only when named | `optional(node)` |
| `defer` | never (announced) | only when named / by group | `defer(node, { group, rescue })` |
| `merge` | resolved | resolved; labels ride partials only | `merge(node, { append, prepend, deep, matchOn })` |
| `once` | resolved unless the client holds it | same | `once(node, { as, until, fresh })` |
| `scroll` | resolved | resolved, with cursors | `scroll(node, { wrapper, pageName, metadata })` |

## What differs from Laravel

The adapter targets feature parity with
[`inertia-laravel`](https://github.com/inertiajs/inertia-laravel) **v3.3.4**
(released 2026-09-11), which is the version every row below was checked against.
Three things are deliberately different:

1. **No session store.** Laravel's flash rides the session; Blok has no session,
   so flash and error bags ride a **signed one-shot cookie**
   (`BLOK_FLASH_SECRET` is required). See [flash data](/d/spa/flash-data).
2. **Middleware is Blok's middleware.** There is no `HandleInertiaRequests`
   class. `inertia.shared`, `inertia.auth` and `inertia.csrf` are ordinary
   middleware **workflows** registered by name. See [middleware](/d/spa/middleware).
3. **Props are steps, not closures.** A prop is a node reference plus its
   inputs, resolved by the runner — which is why a prop can be Python, Go or
   Rust, and why per-prop retries exist at all.

## Packages

| Package | What it is |
| --- | --- |
| `@blokjs/inertia` | the serializer node, `definePage()`, the middleware pack, shared data, routing, errors, SSR |
| `@blokjs/inertia-client` | typed `Pages`/`Routes`, `route()`, and the `blokInertia()` Vite plugin |
| `@blokjs/helpers` | the `@blokjs/flash`, `@blokjs/validate`, `@blokjs/csrf` and `@blokjs/throw` nodes |
| `@inertiajs/react` · `vue3` · `svelte` | the **stock** client, unforked |
