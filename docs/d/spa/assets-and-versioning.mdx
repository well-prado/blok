Counterpart: [Asset versioning](https://inertiajs.com/docs/v3/advanced/asset-versioning).
Laravel computes a version in `HandleInertiaRequests::version()`; Blok reads one
the Vite plugin wrote.

## The Vite plugin

```ts client/vite.config.ts
import { blokInertia } from "@blokjs/inertia-client/vite";
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    react(),
    blokInertia({
      pages: { path: "src/pages", extension: [".tsx"] },
      proxy: { target: "http://localhost:4000" },
      ssr: { entry: "src/ssr.tsx" },
    }),
  ],
});
```

`blokInertia()` **wraps** `@inertiajs/vite`: page resolution, lazy pages, the
SSR transform and the HMR-backed dev SSR endpoint are all upstream behaviour,
and every `@inertiajs/vite` option is passed through. On top it writes into the
Vite `outDir` (`dist/` by default) — the handoff directory the Blok server
reads:

| File / value | What it is |
| --- | --- |
| `dist/.blok-vite.json` | **what to load**: the entry, its stylesheets and its static imports, or the dev server's URL. See below |
| `dist/.blok-asset-version` | sha256 of `dist/.vite/manifest.json`, `"dev"` while the dev server runs. The serializer reads it on every render as the page object's `version` (a page's own `render(..., { version })` still wins), so a rebuild is announced without a restart |
| `import.meta.env.BLOK_ASSET_VERSION` | the same value, inlined into the bundle |
| `dist/pages.json` | `{ root, pages }` — the page components found on disk, for [`ensurePagesExist()`](/d/spa/routing#fail-the-boot-not-the-route) |
| `dist/.blok-ssr-url` + `import.meta.env.BLOK_SSR_URL` | where the server POSTs a page to be [rendered](/d/spa/ssr) |

`build.manifest` is forced on — the asset version is a hash of that manifest, so
turning it off is an error.

## Loading the bundle — Blok's `@vite`

Laravel's Blade template calls `@vite('resources/js/app.jsx')`. Blok's HTML
shell carries a marker, `<!--blok:assets-->`, and the serializer fills it from
`<BLOK_STATIC_DIR>/.blok-vite.json`. Vite hashes its filenames and, in dev,
serves the entry from its own origin, so the tags cannot be hard-coded.

After `vite build` the descriptor names the built files:

```json client/dist/.blok-vite.json
{
  "mode": "build",
  "entry": "assets/index-DucLcArp.js",
  "css": ["assets/index-DCQtc1cu.css"],
  "imports": [],
  "framework": "react"
}
```

and the shell emits, in order, a `<link rel="modulepreload">` per static import,
a `<link rel="stylesheet">` per stylesheet, and the module script:

```html
<link rel="stylesheet" href="/assets/index-DCQtc1cu.css" />
<script type="module" src="/assets/index-DucLcArp.js"></script>
```

While `vite` is running the descriptor points at the dev server instead
(`{ "mode": "dev", "devUrl": "http://localhost:5173", "entry": "src/main.tsx" }`),
and the shell emits `/@vite/client`, the entry, and — for React — the
`@vitejs/plugin-react` refresh preamble, all as absolute URLs. That is what
makes the [dev loop](/d/spa/getting-started#the-dev-loop) work from the *Blok*
URL. The file is deleted when the dev server stops, so a later production boot
never points at a dead port.

<Note>
No descriptor means no `<script>` tag and a blank page, so the server logs one
warning naming the fix and still serves the HTML. The usual causes: the client
was never built, or `BLOK_STATIC_DIR` is not set.
</Note>

A custom `shell` without the `<!--blok:assets-->` marker is left exactly as
written — add the marker inside `<head>`, or pass your own tags as the
serializer's `assets` input.

## The 409 reload

When the client's `X-Inertia-Version` differs from the server's, a **GET**
answers `409` with `X-Inertia-Location: <url>` and the current version, and the
client does a hard visit — the new HTML pulls the new assets. It is never done
on another method: a replayed write would lose its body.

A pending [flash](/d/spa/flash-data) is re-signed onto that 409, so a toast
survives the forced reload.

<Note>
In dev the plugin's proxy attaches `X-Inertia-Version: dev` to every proxied
request, so a dev visit can never 409 on a version mismatch mid-edit.
</Note>

## Serving the build

| Variable | Effect |
| --- | --- |
| `BLOK_STATIC_DIR` | mounts the directory: `/assets/*` with `Cache-Control: public, max-age=31536000, immutable`, plus `favicon.ico` and `robots.txt` uncached. A miss under `/assets/*` is a hard `404`, never a fall-through to a workflow |
| `ASSET_VERSION` | fallback for the page `version` when `<staticDir>/.blok-asset-version` does not exist (the trigger also fills it from that file at boot, for its own log line) |

```bash
BLOK_STATIC_DIR=client/dist blokctl dev
```

With neither set, nothing static is mounted and `version` is `""` — "untracked",
which disables version checking entirely. Nothing in a workflow has to pass
`version`: the value comes from the build, in dev and in production alike.

## Standalone mode and CORS

With the proxy off (`proxy: false`) the SPA is served from its own origin and
talks to Blok cross-origin. Blok must then send CORS headers that cover
Inertia's protocol headers — a missing `Access-Control-Expose-Headers` entry is
invisible in the network tab but makes redirects and version mismatches
unreadable to the client.

```bash
BLOK_CORS_ORIGIN=https://app.example.com
```

Setting it turns on the CORS middleware with `credentials: true` and the full
Inertia / Precognition / DevTools header lists:

```http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
Access-Control-Allow-Headers: X-Inertia, X-Inertia-Version, X-Inertia-Partial-Data,
  X-Inertia-Partial-Component, X-Inertia-Partial-Except, X-Inertia-Reset,
  X-Inertia-Error-Bag, X-Inertia-Devtools-Request, X-Inertia-Devtools-Session,
  Precognition, Precognition-Validate-Only, X-XSRF-TOKEN
Access-Control-Expose-Headers: X-Inertia, X-Inertia-Location, X-Inertia-Redirect,
  X-Inertia-Version, Precognition, Precognition-Success
```

<Warning>
`Access-Control-Allow-Origin` must name the SPA origin explicitly. A value
containing `*` turns credentials **off** — and Inertia sends the session cookie
on every visit, so a wildcard origin silently logs everybody out.
</Warning>

In standalone mode the initial page comes from a JSON fetch rather than a
`data-page` attribute, through `createInertiaApp`'s `page` option, and the types
travel with `blokctl gen app-types --pages-only --out ../my-spa/src`.
