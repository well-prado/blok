Counterpart: [Authentication](https://inertiajs.com/docs/v3/security/authentication)
(Laravel's Breeze / starter kits).

## One command

```bash
blokctl create project --name app --spa react --kit auth
# or, in a project you already have:
blokctl add spa --framework react --kit auth
```

Then `bun run build && bun run start` and open `/login`. Register, sign in, land
on `/dashboard`, sign out — with **zero edits**. `--framework vue` and
`--framework svelte` ship the same screens.

<Note>
`--kit` needs a client to put the pages in, so it only works alongside
`--spa <framework>` (or on `add spa`). It is refused, not ignored.
</Note>

## What you get

| Route | Page | What runs |
| --- | --- | --- |
| `GET /login` | `Auth/Login` | — |
| `POST /login` | — | validate → `login` (throttled 5/min per IP+email) → 303 |
| `POST /logout` | — | destroy session, `clearHistory`, rotate CSRF → 303 |
| `GET /register` | `Auth/Register` | — |
| `POST /register` | — | validate → `register` → new session → 303 |
| `GET /forgot-password` | `Auth/ForgotPassword` | — |
| `POST /forgot-password` | — | issue a single-use token, same answer either way |
| `GET /reset-password/:token` | `Auth/ResetPassword` | the token, as a prop |
| `POST /reset-password/:token` | — | spend the token, set the password → 303 |
| `GET /dashboard` | `Dashboard` | guarded by [`inertia.auth`](/d/spa/middleware) |

On disk:

- `src/workflows/auth/*.ts` — one file per route. Each one routes a workflow
  from `@blokjs/auth/examples`; paste the workflow's source in to make it yours.
- `client/src/pages/Auth/*` and `client/src/pages/Dashboard.*` — the components,
  plus a `GuestLayout` and the kit's own `styles/auth.css`.
- `src/Workflows.ts` — one spread registers `inertia.session`,
  `inertia.shared`, `inertia.csrf` and `inertia.auth`.
- `src/Nodes.ts` — `SESSION_NODES` and `AUTH_NODES` (npm packages are registered
  explicitly; only `src/nodes/**` is auto-discovered).
- `.env.local` — a generated `BLOK_SESSION_SECRET` and `BLOK_FLASH_SECRET`, and
  `BLOK_GLOBAL_MIDDLEWARE=inertia.session,inertia.shared,inertia.csrf`. The
  order matters: the session has to be loaded before the `auth` shared prop is
  resolved. `.env.example` gets the same block with the secrets blank.

Every page carries an `auth` prop:

```ts
// what `@blokjs/auth`'s currentUser node publishes
type Auth = {
  id?: string; // absent for a guest — `inertia.auth` gates on it
  user: { id: string; name: string; email: string } | null;
};
```

`blokctl gen app-types` picks all of this up from the Zod output schemas, so
`PageProps<"Dashboard">` is typed without you writing a type.

## No ORM

The kit persists through a six-method interface. The default implementation is
SQLite (`better-sqlite3` under Node, `bun:sqlite` under Bun); point it at
anything else by handing `configureAuth` your own:

```ts src/auth.ts
import { type AuthUser, type UserStore, configureAuth } from "@blokjs/auth";

/** Sketch: the same six methods over whatever database you already run. */
declare const db: {
  query: (sql: string, params: unknown[]) => Promise<AuthUser[]>;
  run: (sql: string, params: unknown[]) => Promise<void>;
};

const users: UserStore = {
  async findByEmail(email) {
    return (await db.query("select * from users where email = $1", [email]))[0];
  },
  async findById(id) {
    return (await db.query("select * from users where id = $1", [id]))[0];
  },
  async create(user) {
    const rows = await db.query(
      "insert into users (name, email, password_hash) values ($1, $2, $3) returning *",
      [user.name, user.email, user.passwordHash],
    );
    return rows[0] as AuthUser;
  },
  async updatePassword(id, passwordHash) {
    await db.run("update users set password_hash = $1 where id = $2", [passwordHash, id]);
  },
  async createResetToken(record) {
    await db.run("insert into password_resets (user_id, token_hash, expires_at) values ($1, $2, $3)", [
      record.userId,
      record.tokenHash,
      record.expiresAt,
    ]);
  },
  async consumeResetToken(tokenHash) {
    const rows = await db.query("delete from password_resets where token_hash = $1 returning user_id", [tokenHash]);
    const row = rows[0] as { user_id?: string } | undefined;
    return row?.user_id ? { userId: row.user_id } : undefined;
  },
};

configureAuth({ users, redirectAfterLogin: "/dashboard" });
```

Drizzle, Prisma or a hand-rolled repository all fit the same six methods — none
of them is a dependency of Blok.

## Sending the reset email

With no mailer configured the reset link is **logged**, the way Laravel's `log`
mail driver works, so the flow runs before you have email. Wire yours once:

```ts src/mail.ts
import { configureAuth } from "@blokjs/auth";

configureAuth({
  async sendResetLink({ email, url }) {
    await fetch("https://api.example-mailer.com/send", {
      method: "POST",
      body: JSON.stringify({ to: email, subject: "Reset your password", body: url }),
    });
  },
});
```

The raw token reaches this callback and nowhere else — it is never a step
output, so it cannot land in `ctx.state`, a trace or DevTools.

## What it is made of

Nothing here is a new framework layer; the kit is a generator over modules you
can install on their own:

- [`@blokjs/session`](/d/spa/middleware) — a signed, `HttpOnly`,
  `SameSite=Lax` cookie carrying an opaque session id, with the data in a
  pluggable store (`memory`, `sqlite` by default, `redis` when `REDIS_URL` is
  set). Rotated on sign-in and sign-up, destroyed on sign-out.
- `@blokjs/auth` — scrypt password hashing (`node:crypto`, no native addon),
  the auth nodes, login throttling, and single-use reset tokens stored hashed.
- The existing [middleware chain](/d/spa/middleware),
  [CSRF](/d/spa/csrf), [flash](/d/spa/flash-data),
  [validation](/d/spa/validation) and
  [history encryption](/d/spa/history-encryption).

Security properties worth knowing: sign-in answers the same message (and costs
the same wall-clock time) for an unknown address as for a wrong password;
`forgot-password` answers the same way whether or not the address exists;
sign-out clears the client's history and rotates the CSRF token; and no
password, hash, session id or reset token is ever a step output.
