Counterpart: [Routing](https://inertiajs.com/docs/v3/the-basics/routing).
Laravel has Ziggy and Wayfinder; Blok generates the same shape from the
workflows themselves.

## Typed routes on the client

The types describe the call signature; the URL patterns arrive at runtime. Both
are generated by `blokctl gen app-types`, or written by hand once:

```ts client/src/routes.ts
import { registerRoutes, route } from "@blokjs/inertia-client";

// `blok-pages.d.ts` writes this half for you.
declare module "@blokjs/inertia-client" {
  interface Routes {
    "orders.index": { method: "get"; component: "Orders/Index" };
    "orders.show": { params: { id: string }; method: "get"; component: "Orders/Show" };
  }
}

registerRoutes({
  "orders.index": { url: "/orders", method: "get", component: "Orders/Index" },
  "orders.show": { url: "/orders/:id", method: "get", component: "Orders/Show" },
});

export const index = route("orders.index").url;              // "/orders"
export const show = route("orders.show", { id: "1" });       // a UrlMethodPair
export const instant = route("orders.show", { id: "1" }).withComponent("Orders/Show");
export const asString = `${route("orders.show", { id: "1" })}`; // "/orders/1"
```

`route()` returns a Wayfinder-shaped object — an Inertia `UrlMethodPair` — so it
goes straight into `href`, `action` and `router.visit()`, and the client infers
the method from it. Params the pattern does not consume become query-string
entries. A placeholder with no value **throws**, naming the parameter:
`/orders/undefined` is the failure this exists to prevent.

Route names are the **workflow** names, methods are lowercased, and `component`
appears only when the workflow renders a page.

## A route with no controller

Laravel's `Route::inertia()`:

```ts src/Workflows.ts
import { inertia } from "@blokjs/inertia";

export default {
  about: await inertia.page("/about", "About", { team: "Blok" }),
};
```

One generated workflow, one step, no workflow file. A fourth argument takes
`{ name, middleware, inputs }` for the workflow name, a middleware chain, or
extra serializer inputs (`version`, `viewData`, `shell`, …). Shared data,
`resolveUrlUsing` and `transformComponentUsing` all apply to it, because they
live in the serializer.

## Adapter-wide overrides

```ts src/url-overrides.ts
import { resolveUrlUsing, transformComponentUsing } from "@blokjs/inertia";

resolveUrlUsing((req: unknown) => new URL(String((req as { url?: string }).url), "http://x").pathname);
transformComponentUsing((name: string) => name.toLowerCase());
```

Both are set once at boot. The URL resolver **wins over a page's own `url`** —
every page passes one (it is a required `render()` argument), so an override
that lost to it would never apply. The component transform runs before the name
is emitted and before `ensurePagesExist` checks it.

<Warning>
A component transform is **not** seen by the `page` control step, which compares
`X-Inertia-Partial-Component` against the untransformed name. The wire output
stays correct (the serializer narrows), but the step resolves the full prop set
on such a partial, and an `optional`/`defer` prop asked for by name will not
resolve. Prefer naming components the way the client spells them.
</Warning>

## Fail the boot, not the route

```ts src/ensure.ts
import { ensurePagesExist } from "@blokjs/inertia";

await ensurePagesExist();   // on unless NODE_ENV=production
```

Checks every `definePage()` component — and every `inertia.page()` one — against
the `pages.json` the Blok Vite plugin writes into its `outDir`, and throws
naming the missing components plus a `Fix:` line. The manifest is looked up at
`$BLOK_STATIC_DIR/pages.json` (override with `{ manifest }` / `{ dir }`); when it
is absent the check **warns and skips**, so booting the server before the client
has ever been built still works.
