`blokctl gen app-types` generates the `BlokApp` type — a types-only
`blok-app.d.ts` that indexes every TypeScript workflow by its dotted name. The
[typed client](/d/client/overview) imports it to infer every call.

## `gen app-types`

```bash
blokctl gen app-types [--dir <path>] [--out <file|dir>] [--pages-only] [--with-all-errors] [--watch] [--dry-run]
```

| Flag | Description |
|---|---|
| `-d, --dir <path>` | Directory of TypeScript workflow files to scan. Defaults to the first of `triggers/http/src/workflows`, `src/workflows`, `workflows/ts`, or `workflows` that exists. |
| `-o, --out <file\|dir>` | Output file (defaults to `./blok-app.d.ts`), or — with no `.ts` suffix — the DIRECTORY every generated file is written into. A standalone SPA passes `--out ../my-spa/src`. |
| `--pages-only` | Write only the Inertia files (`blok-pages.d.ts`, `blok-routes.ts`). |
| `--with-all-errors` | The app uses `withAllErrors`, so `errors` values are typed `string[]` instead of `string`. |
| `--watch` | Regenerate whenever a workflow file changes. |
| `--dry-run` | Print the generated files instead of writing them. |

## What it scans

For `blok-app.d.ts` the generator reads each TypeScript workflow file and
extracts its `name` statically — it does not run your code. Both spellings are
recognised: the callback DSL's first argument (`workflow("users.list", { … })`)
and the object DSL's `name:` key. A workflow whose name is a variable is
skipped.

JSON-authored workflows are skipped: there is no TypeScript type to import. A
codegen path for JSON, non-TypeScript, and cross-repo clients is
[planned](/d/client/overview#what-ships-today).

## The generated file

For workflows named `users.list`, `users.create`, and `health`:

```ts blok-app.d.ts
// AUTO-GENERATED by `blokctl gen app-types`. Do not edit by hand.
// Regenerate after adding, removing, or renaming a workflow.
// Consumed by `@blokjs/client`: `createBlokClient<BlokApp>()`.

import type usersList from "./triggers/http/src/workflows/users/list";
import type usersCreate from "./triggers/http/src/workflows/users/create";
import type health from "./triggers/http/src/workflows/health";

export type BlokApp = {
  users: {
    list: usersList;
    create: usersCreate;
  };
  health: health;
};
```

The dotted name drives the nesting: `users.list` becomes `BlokApp.users.list`;
a plain `health` stays at the top level.

## Inertia apps: `blok-pages.d.ts` and `blok-routes.ts`

When the project depends on `@blokjs/inertia`, the same run also emits the two
files a Blok SPA needs. This half DOES import your workflow modules: page prop
types come from the Zod output schemas that `definePage()` records, and those
only exist at runtime. A module that throws is reported with its file and
message, the other pages are still written, and the command exits non-zero.

```ts blok-pages.d.ts
// AUTO-GENERATED by `blokctl gen app-types` — do not edit by hand.
import "@blokjs/inertia-client";
import "@inertiajs/core";

declare module "@blokjs/inertia-client" {
  interface Pages {
    "Orders/Index": {
      orders: Array<{ id: string; total: number }>;
      stats?: { revenue: number };
    };
  }

  interface Routes {
    "orders.index": { method: "get"; path: "/orders"; component: "Orders/Index" };
    "orders.show": { params: { id: string }; method: "get"; path: "/orders/:id"; component: "Orders/Show" };
  }
}

declare module "@inertiajs/core" {
  interface InertiaConfig {
    sharedPageProps: Record<never, never>;
    flashDataType: Record<string, unknown>;
    errorValueType: string;
  }
}
```

- `optional()` and `defer()` props become optional keys; every other mode stays
  required.
- A prop resolved by a `runtimeNode()` stub has no Zod schema, so it is typed
  `unknown` and listed in a warning.
- Route names are workflow names, methods are Inertia's lowercase spelling, and
  `component` appears only when the workflow renders a page.

The types alone cannot build a URL, so `blok-routes.ts` carries the patterns at
runtime. Import it once from the SPA entry:

```ts blok-routes.ts
// AUTO-GENERATED by `blokctl gen app-types` — do not edit by hand.
import { registerRoutes } from "@blokjs/inertia-client";

registerRoutes({
  "orders.index": { url: "/orders", method: "get", component: "Orders/Index" },
  "orders.show": { url: "/orders/:id", method: "get", component: "Orders/Show" },
});
```

A project without `@blokjs/inertia` skips all of this with one info line — it is
never an error.

## Name collisions

Names must be unique — see the
[naming convention](/d/introduction/workflows#naming-convention). When two
workflows resolve to the same path, or a name is both a leaf and a group (for
example `users` and `users.list`), the generator drops the conflicting one and
warns:

```
⚠️  name collision — "users" overlaps another workflow's path and was dropped.
```

Generation still completes, but the dropped workflow is missing from `BlokApp`,
so the client can't reach it. Rename one of the workflows and regenerate.

## When to run it

The type is not regenerated automatically. Run it whenever you add, remove, or
rename a workflow — and wire it into your prebuild so a committed `blok-app.d.ts`
never goes stale:

```json package.json
{
  "scripts": {
    "prebuild": "blokctl gen app-types"
  }
}
```

A stale `BlokApp` is a type-versus-runtime mismatch: the client's types won't
match what the server actually runs.
